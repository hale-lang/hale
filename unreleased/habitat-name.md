- Every organism the habitat grafted is handed the habitat's name as `HALE_DNA_HABITAT_NAME`: its services' compose project wherever it is applied (here, or on the command line before compose on an `ssh` host, shell-quoted like `HALE_SECRET_*`), a repository body's compose services when the habitat grafted the organism, and each run of a host command (`hale habitat organism place|unplace`, through `env` so sudo keeps it). As with its secrets, it reaches a service only as the compose file passes it; a models provider names what it keeps for the habitat it serves by it. The habitat's own genome is now a tenant of its models too: whenever a models provider is grafted (and with `hale habitat models --all`, or `hale habitat models habitat`), the provider's key family gets a member labelled `habitat`, copied into the genome's slot `model-HABITAT_<KEY>`, and the genome's model map is seeded as a tenant's. Since a provider names a tenant's project by its label, grafting an organism called `habitat` is refused.
- A models provider's `grant` sentence (`[dna.provides.models] grant`) may say `{habitat}` beside `{organism}`: the habitat fills it with its name, the one its services are handed as `HALE_DNA_HABITAT_NAME`.

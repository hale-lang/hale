### Breaking
- `hale check` now refuses an `or raise` whose call fails with a different error type than the enclosing fn declares (GH #1945). Before, the check passed it and `hale build` failed with a codegen error. The refusal points at the `or raise` and names both types. Translate the error with `or fail E { … }` (the call's error is in scope as `err`), or declare the fn `fallible` with the call's error type.

### Deprecated
- `std::json::Builder`'s `field(name, value)` and `value(v)` are deprecated, and each call warns `deprecated:` (GH #1943). They write their argument raw, although the spec described them as taking a string, so `b.field("name", "alice")` writes `"name": alice`, which is not JSON. This release does not change what they write. The new `raw_field(name, json)` / `raw_value(json)` write JSON you encoded already, byte for byte; `string_field` / `string_value` quote and escape a string. v0.33 makes `field` and `value` quote their argument as a string, so a call that hands them encoded JSON should move to `raw_field` / `raw_value` now. Every caller in this repository has moved. The separators stay `": "` and `", "`, and the spec now states them. The warning comes from a new table of deprecated stdlib callables, which later deprecations reuse.

### Fixed
- A wire map (`bounded[T; N] indexed_by k`) never decodes input it cannot represent as an empty value (GH #1944). A member that is not the record's JSON, such as an array where an object belongs, is `wrong_type` naming the field, and so is a map sent as anything but an object. Before, `{"bars":{"AAPL":[…]}}` decoded as `AAPL` with no rows. A `json:`-tagged or `@positional` record with an `indexed_by` field now has a working `from_json` / `to_json`. Before, it was refused with the names of generated helpers and no location. The hot-path lint no longer warns inside compiler-generated codecs.
- Qualified stdlib error types (`fallible(std::crypto::CryptoError)`, `std::io::IoError`, `std::index::IndexError`, `std::form::hashmap::KeyError`, `std::form::ring_buffer::EmptyError`) build wherever the bare names do (GH #1945). Before, the check passed them and the build failed with no location.
- `api::serve` no longer fails the build at 17 receiver types (GH #1946). One exposure now dispatches to up to 100 receiver types, and a serve site past that is refused by `hale check` at its `receivers:`. Before, a 17th receiver passed the check, also skipped the check's validation of the call, and failed the build.

### Added

- Optional record fields (GH #1951 item 3): `x?: T` in a `type` declares `x` and a real presence flag `has_x: Bool = false` right after it, and `x?: T clearable` a `clear_x: Bool = false` too: the presence pair and triple the api codecs read, so the JSON and protobuf wires, a surface's description and its contract digest are byte-identical to the hand-written pair, and converting one changes no shape hash. A write of `x` (a literal that spells it, an assignment through any path or into a part of it, a `push` or `set` into an optional list) sets `has_x` and clears `clear_x`; a literal that leaves `x` out builds it absent, at its default or its type's zero (a type with no zero is refused at the field, asking for a default). Declaring the synthesized flag beside the mark is a duplicate field. Optionality is a property of a record field, never a type (F.51): `?` on a parameter, a locus param or a local, `T?` after any type, and `?` on a `@positional` record's field are parse errors. `clearable` joins the contextual keywords, a word only after an optional field's type, so no program that built before stops building. Hand-written pairs keep working as before.
- `hale api import` writes an optional property as `name?: T;` instead of a hand-written `has_name` pair. Its flag now follows the field, so a re-imported record's field order, and with it its shape hash, differs from an earlier import's.

### Changed

- The JSON encoder leaves out an optional `std::json::Value` field that holds `null` instead of writing `null`: read back, an optional field's `null` was its absence and a clearable field's its clear flag, so the written `null` could not round-trip.

Breaking: none

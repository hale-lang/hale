- `std::json::valid` and `valid_object` accept `\u0000` and an unpaired UTF-16 surrogate escape (`\ud800` with no low escape after it, a bare `\udc00`) inside a string. RFC 8259 allows any `\uXXXX`, and producers emit them (a tool output that read a binary file carries them); they were refused, so `{"a":"x\u0000y"}` failed `valid_object`, and what is gated on it (an MCP message, a hub datagram) was turned away. Every reader decodes them as `unescape_string` already did, to U+FFFD (a `String` is NUL-terminated, and a lone surrogate has no UTF-8); a valid pair still combines. Downstream handoff.

Breaking: none

### Docs

- A new book page, [Running Without a Habitat](docs/src/getting-started/without-a-habitat.md), takes a service from source to a process with no habitat: `hale run` and `hale build`, serving an API, configuration from argv and the environment, the probe and metrics endpoints, SIGTERM drain, a systemd unit, a container image, and when a habitat is what you want instead.
- The spec and the book describe the habitat as shipped: it runs under the `local` profile, on this machine or another over SSH. The unbuilt `hosted` profile is no longer described.
- `spec/api.md` says what ships: an imported surface is called through `api::client`, and an OpenAPI document may be YAML. The open points keep only what the import does not read: Swagger 2.0, header and cookie parameters, error responses, security schemes, and a `$ref` to another document. The book's client outcome mapping now matches the client: `403` is a handler error with the class `forbidden`, not a refusal, and `503` is a handler error with the class `unavailable`.

### Changed

- `hale habitat up --help` says `--profile` takes `local`, and `up --profile <other>` names what `up` takes, not a profile that is not built.

# The Todo contract

What `api` serves: one surface, `Todo`, and one stream, `TodoChanged`. The
files beside this one are the same rows in machine form, generated by `hale api
export --surface Todo --out spec/ api` and held to the program by a test; this
page is the one a reader starts from, and its digest is checked against
[`DIGEST`](./DIGEST).

Surface digest: `fnv1a64:67bff1470a7912dc`.

## Calls

Over HTTP (`POST /call/<member>`, a bearer token), over MCP (a tool per
member, `Todos__add`) and as a call frame on the stream's hub.

| Member | Needs | Request | Answer | Error |
|---|---|---|---|---|
| `Todos::add` | `editor` | `title`, `due` (ISO-8601 UTC, optional) | the item | `empty_title`, `bad_due`, `full` |
| `Todos::complete` | `editor` | `todo` (the item's number) | the item | `unknown_item` |
| `Todos::remove` | `editor` | `todo` | the item | `unknown_item` |
| `Todos::list` | `reader` | `open_only` (optional) | `count` and the items as a JSON array in `json` | none |
| `Todos::overdue` | `reader` | none | the same, for the items past their `due` | none |

An item is `{id, title, done, due, overdue}`; `due` is empty for none. `editor`
includes `reader`.

## Stream

`TodoChanged` is bound to a WebSocket hub for `reader`s: `{what, item}` where
`what` is `added`, `completed` or `removed`, in the order the list changed. A
subscriber that cannot keep up loses the oldest events (`drop_old`, 64 queued),
and a gap in `seq` shows it.

### Changed

- Every `std::io::fs` call that reaches the file system is classified `block` as well as `syscall`. The calls are `read_file`, `read_bytes`, `write_file`, `write_bytes`, `write_file_append`, `rename`, `unlink`, `mkdir`, `mktemp`, `file_size`, `file_exists`, `list_dir_count` and `list_dir_at`. The docs and spec already said a file call blocks, but the effects registry did not. Now the `async_io` placement advisory and the classic-pool advisory warn on a file call, and `@no_block` refuses one. `extension` reads only its argument and is unchanged (GH #2032).

### Breaking

- A fn under `@no_block` or `@effects(none: {block})` that reaches a `std::io::fs` call other than `extension`, directly or through a helper, is refused ("must not reach `block`"). So is a cooperative subscriber whose `run()` makes such a call (the dead-receiver error). Migration: move the file I/O out of the asserted fn, for example into a `pinned` locus that the fn reaches over the bus, or drop `block` from the assertion where waiting on the disk is acceptable. A `run()` that does file I/O on a cooperative pool belongs on `pinned`.
